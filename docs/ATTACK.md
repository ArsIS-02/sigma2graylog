# Теги MITRE ATT&CK

Sigma-правило описывает тактику и технику тегами:

```yaml
tags:
  - attack.execution
  - attack.t1059.001
```

При создании детекта конвертер записывает их в определение события Graylog полями
(`field_spec`, шаблон `template-v1` со статическим текстом):

| Поле | Пример | Что внутри |
|---|---|---|
| `mitre_tactic` | `Execution` | тактика основной техники |
| `mitre_technique` | `T1059.001 PowerShell` | основная техника (первая в тегах) |
| `mitre_techniques` | `T1059.001, T1105` | все техники правила |

В карточке правила показана метка «ATT&CK»: основная техника и тактика, по наведению весь список.

## Описание детекта

К описанию определения добавляется строка с тактиками и техниками, исходный текст остаётся:

```
В командной строке использован /dev/tcp.
MITRE ATT&CK. Тактики: Execution. Техники: T1059.004 Unix Shell.
```

В строку входят все тактики, в которые входят техники правила (основная первой), и список техник с
названиями. Повторный вызов строку не дублирует: всё, что начинается с `MITRE ATT&CK.`, заменяется.

## Вкладка «Покрытие ATT&CK»

Показывает матрицу ATT&CK и подсвечивает техники, на которые в Graylog есть определения событий.
Данные читаются из самого Graylog при каждом открытии вкладки (поля `mitre_*` определений), ничего
отдельно обновлять не нужно. Чем темнее клетка, тем больше определений закрывают технику; по
клику видно, какие именно. Определения без техник перечислены под матрицей.

Кнопка «Слой для Navigator» скачивает JSON для ATT&CK Navigator (Open Existing Layer → Upload
from local). API: `GET /api/attack/coverage` (матрица), `GET /api/attack/layer` (слой).

Определения, созданные не через конвертер (вручную или другими инструментами), попадают в матрицу,
если в их `field_spec` есть поля `mitre_technique` / `mitre_techniques` со значениями вида
`T1059.001 PowerShell` и `T1059.001, T1105`.

## Правила разбора

- Тактика берётся у основной техники. Если у техники несколько тактик, выбирается первая из
  тегов правила, которая ей подходит, иначе первая по справочнику. Если техники нет, берётся
  первый тег тактики.
- Справочник: ATT&CK v20 (`app/attack_v20.json`). В v20 часть идентификаторов заменена:
  `T1562.001` → `T1685`, `T1562.004` → `T1686`, `T1070.001` → `T1685.005`,
  `T1070.002` → `T1685.006` и т. д. Старые теги переводятся автоматически (см. `RENAMED` в
  `app/attack.py`).
- Тактика `attack.defense-evasion` в v20 разделена на `stealth` и `defense-impairment`. В
  справочнике её нет, и без тега техники она игнорируется. Есть технический тег
  (например `attack.t1070`), тактика определяется по нему.
- Идентификатор, которого нет в справочнике, но по форме корректный (`T1234`), записывается как
  есть, без названия.
- Значения проверяются на сервере: принимаются только идентификаторы вида `T1234` и `T1234.001` и
  известные тактики, остальное отбрасывается.

## Где искать в Graylog

В событиях пользовательские поля лежат во вложенном объекте `fields`, поэтому в поиске по потоку
`All events` пишется `fields.mitre_technique`, а не `mitre_technique`. Поля появляются только в
событиях, созданных после записи определения.
