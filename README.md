**Конвертер Sigma-правил в детекты Graylog — с привязкой к полям, которые реально есть в ваших индексах.**

Правила Sigma написаны в терминах Windows-полей: `Image`, `CommandLine`, `EventID`.
В Graylog те же данные лежат иначе: `winlogbeat_winlog_event_data_Image`, `exe`, `proctitle`, `name`.
Скопированный наугад Sigma-запрос обычно превращается в запрос, который молча не находит ничего.

Инструмент закрывает этот разрыв: разбирает правило через [pySigma](https://github.com/SigmaHQ/pySigma),
определяет продукт правила, выбирает соответствующий стрим, сопоставляет каждое поле с реальным
списком полей этого стрима, переписывает запрос в синтаксис, который Graylog принимает, и показывает,
насколько правило шумное на ваших исторических данных — **до** создания детекта.

## Быстрый старт: демо без Graylog

```bash
git clone https://github.com/ArsIS-02/sigma2graylog.git
cd sigma2graylog
docker build -t sigma2graylog:latest .
docker run -d --name sigma2graylog-demo -p 8080:8080 -e DEMO_MODE=1 sigma2graylog:latest
```

Откройте http://localhost:8080 — приложение работает на синтетических данных, вход не требуется.
Демо-режим (`DEMO_MODE=1`) полезен и для скриншотов: реальные имена хостов и полей не светятся.

## Быстрый старт: реальный Graylog

```bash
cp .env.example .env
# заполнить GRAYLOG_URL, GRAYLOG_USER, GRAYLOG_PASSWORD, APP_PASSWORD
docker build -t sigma2graylog:latest .
docker run -d --name sigma2graylog --restart unless-stopped \
  -p 8080:8080 --env-file .env -v s2g-data:/data sigma2graylog:latest
```

Откройте http://localhost:8080, войдите под `APP_USER` / `APP_PASSWORD`, затем укажите параметры
подключения во вкладке **«Настройки»** — интерфейс проверит их живым запросом к `/api/system`.

Для Podman замените `docker` на `podman` и добавьте `:Z` к тому: `-v s2g-data:/data:Z`
(обязательно на системах с SELinux).

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `GRAYLOG_URL` | адрес Graylog, например `http://graylog.example.com:9000` |
| `GRAYLOG_PUBLIC_URL` | адрес для ссылок в интерфейсе (должен резолвиться с рабочей машины) |
| `GRAYLOG_USER` / `GRAYLOG_PASSWORD` | сервисная учётная запись |
| `GRAYLOG_TOKEN` | альтернатива паре логин/пароль |
| `APP_USER` / `APP_PASSWORD` | доступ в интерфейс, используется **только** для создания первого пользователя |
| `FIELDS_TTL` | кэш списка полей, секунды (по умолчанию 600) |
| `DEMO_MODE` | `1` — синтетические данные, внешний Graylog не нужен |
| `ALLOW_PRIVATE_URLS` | `1` — разрешить загрузку «По ссылке» с внутренних адресов (по умолчанию они заблокированы) |

Значения из вкладки «Настройки» перекрывают переменные окружения: они хранятся в
`/data/settings.json` с правами `0600`, секреты шифруются (Fernet, ключ выводится из
`/data/secret.key`) и в браузер не возвращаются.

## Как работает сопоставление полей

1. **Каждому стриму определяется продукт** по составу полей его событий:
   `winlogbeat_*` → windows, `audit_type` / `proctitle` → linux, `macos_*` → macos.
   Считается по выборке последних событий и кэшируется на 10 минут.
2. **Продукт правила выбирает стрим**, и пространством маппинга становится реальный набор полей
   этого стрима, а не глобальный список. Правило `product: linux` уже не может быть смапплено
   на `winlogbeat_*`.
3. **Семантический словарь** закрывает типовые случаи: в auditd `CommandLine` — это `proctitle`,
   `Image` — `exe`, `TargetFilename` — `name`; в Windows `Image` — `win_image` или
   `winlogbeat_winlog_event_data_Image`, что чаще встречается в выборке.
4. **Оценка уверенности** ранжирует кандидатов; всё ниже 70 помечается как «поле не найдено»
   со списком подсказок, а не подставляется молча.

## Особенности Graylog, которые пришлось обойти

Проверено на Graylog 7.2.1:

| Запрос | Поведение |
|---|---|
| `field:*value*` | **ошибка разбора** — leading wildcard без кавычек не принимается |
| `field:"*value*"` | разбирается, но не находит ничего |
| `field:/.*value.*/` | работает — именно в такой вид компилируются `contains`/`endswith` |
| `TASKHOSTW.EXE` | 0 совпадений: regex в Graylog регистрозависимый, Sigma — нет |

Внутри значения `*` Sigma означает «любые символы», `?` — «один символ»: в regex они превращаются
в `.*` и `.`, а `/`, `"`, `&`, `#`, `~`, `<`, `>` и другие символы, значимые для Lucene-regex,
экранируются. Кавычки и экранирование (`\"`, `\ `) разбираются посимвольно, поэтому значения вида
`say "hi" there` не ломают запрос, а `*` внутри фразы в кавычках не трогается.

Отсюда два решения: ведущий wildcard всегда переводится в regex, а регистронезависимость
включается раскрытием букв в символьные классы (`[Pp]ower[Ss]hell`) — по умолчанию включено,
отключается в настройках.

Ещё три момента по API: `POST /api/events/definitions` требует обёртку `{"entity": {...}}`
с пустым массивом `series`, `DELETE` требует заголовок `X-Requested-By`, а удаление и создание
сбрасывают кэш определений.

## Вкладки

**Конвертер** — основная работа: правило → запрос, маппинг, проверка, история, создание детекта.

**Стримы** — анализ: список стримов с продуктом, объёмом и числом полей; по клику — покрытие
типовых полей Sigma, ручной маппинг и генератор экстракторов.

**Детекты** — что уже есть в Graylog: поиск, фильтр «без срабатываний», дата последнего
срабатывания, ссылка на определение, копирование запроса, удаление с подтверждением.

**Настройки** — подключение к Graylog и параметры по умолчанию.

### Пакетный режим

Если в редактор загружено больше одного правила, результат показывается таблицей: правило,
уровень, определённый стрим, статус (`готов` / `дубль` / `ошибка` / `нет запроса`). Клик по
названию раскрывает карточку с запросом и маппингом. Сверху — фильтры «все / готовые /
с ошибками / high+» и кнопка **«Создать выбранные»**: подтверждение со списком, затем
`POST /api/event-definitions/bulk`, отчёт «создано / пропущено дублей / ошибок».
Дубли (совпадение ≥ 0.8) пропускаются, лимит — 50 правил за раз.

### Прогон по истории

Один pivot-запрос (`/api/views/search/sync`, группировка `timestamp/1d`) — не 30 отдельных
запросов. Возвращает раскладку по дням, сумму, максимум за сутки, среднее и вердикт:
0 — «не срабатывает ни разу», до 100 в сутки — умеренно, 100–1000 — шумновато,
больше 1000 — очень шумно. Плюс три примера реальных событий.

### Проверка дублей

Запрос сравнивается со всеми существующими детектами: Jaccard по токенам запроса (без регистра
и пунктуации) и сходство названий. Совпадение от 55% показывается блоком «Похожий детект уже есть»
со ссылкой и процентом; при полном совпадении запроса так и пишется.

## Источники правил

В конвертере есть **«Библиотека наборов»** — публичные наборы правил. Каждый набор раскрывается:
видны число правил, дата загрузки и разбивка по продуктам; можно загрузить набор целиком или
только один продукт. Новый набор добавляется кнопкой **«＋ из каталога»**, ⟳ обновляет список.
Наборы каталога:

| Источник | Что это |
|---|---|
| SigmaHQ — все правила | релизный архив `sigma_all_rules.zip`, ~3000 правил, 3.2 МБ |
| SigmaHQ — core | курируемое ядро, 1.4 МБ |
| SigmaHQ — master (tar.gz) | текущее состояние репозитория, включая правила вне релиза |
| ThreatHunting Keywords (mthcht) | правила для threat hunting по ключевым словам |
| SIGMA detection rules (mdecrevoisier) | практические правила по Windows/AD |

Фильтры (продукт, уровень, лимит выдачи — 50 / 100 / 200 / 300) расположены в шапке библиотеки.
После первой загрузки в селекты подставляются реальные значения из набора. Загрузка кэшируется в `/data/sources/<id>.json` на 24 часа:
SigmaHQ core в первый раз — около 6 секунд, повторный запрос — меньше секунды.

Клон репозитория не нужен: релизный архив весит 3.2 МБ вместо 48 МБ и качается за секунды.

## Загрузка правил

| Способ | Что принимает | Лимиты |
|---|---|---|
| **Файлы…**, **Папка…** или drag&drop | `.yml`, `.yaml`, `.zip`, `.tar.gz`, `.tgz`, каталог с правилами | 3000 файлов, 8 МБ на файл |
| поле **по ссылке** | URL на YAML, zip или tar.gz | 25 с на скачивание, 64 МБ; внутренние адреса заблокированы (см. ниже) |
| API `/api/load/files`, `/api/load/url` | то же | — |

**Защита от SSRF.** Загрузка по ссылке и скачивание наборов не ходят на localhost, частные сети
(10.x, 172.16–31.x, 192.168.x), link-local (169.254.x, метаданные облака) и IPv6 loopback/ULA.
Адрес проверяется до запроса и заново на каждом редиректе (до 5), размер ограничивается во время
чтения, а не после полной загрузки. Свой внутренний источник включается переменной
`ALLOW_PRIVATE_URLS=1`.

Правила проверяются через pySigma, не-Sigma файлы и битый YAML отбрасываются, дубликаты по `id`
отсеиваются, служебные каталоги (`.git`, `tests`, `deprecated`) пропускаются.
В редактор попадает до 300 правил, конвертируется за раз до 60 — с пометкой об усечении.

## Экстракторы для отсутствующих полей

Во вкладке «Стримы» у непокрытого поля есть кнопка **«сделать экстрактор»**: она собирает
готовое правило pipeline для Graylog.

```
rule "sigma2graylog — file_path_full"
when
  has_field("cwd") && has_field("name")
then
  let combined = to_string($message.cwd) + "/" + to_string($message.name);
  set_field("file_path_full", combined);
end
```

Остаётся вставить правило в System → Pipelines, подключить к стриму и выбрать новое поле
в маппинге. Порядок исходных полей важен: для auditd сначала `cwd`, потом `name`.

## Вход и пароли

Логин и пароль хранятся не в `.env`, а в `/data/users.json` — scrypt с солью, права `600`.
`APP_USER` / `APP_PASSWORD` используются один раз, при первом старте.

- Страница входа `/login`.
- Смена пароля — меню под аватаром: требует текущий пароль, минимум 8 символов, после смены
  остальные сессии разлогиниваются, текущая перевыпускается автоматически.
- Сессия живёт 12 часов, подписана HMAC-SHA256, секрет — `/data/secret.key`.
- Защита от перебора: 8 неудачных попыток с одного IP за 5 минут → `429`.

Сброс пароля при утере:

```bash
sudo podman exec sigma2graylog python -c "
from app.auth import UserStore; from pathlib import Path
u=UserStore(Path('/data/users.json')); u.set_password('sigma','НОВЫЙ_ПАРОЛЬ'); print('ok')"
sudo podman restart sigma2graylog
```

## Ограничения

- Значения с `*` внутри (`foo*bar`) и `?` в `contains`/`endswith` переводятся в regex (`.*`, `.`).
- Регистронезависимость делается символьными классами: длинное значение раскрывается до 48
  символов, выше — остаётся обычный regex с предупреждением.
- Список полей стрима строится по выборке из 100 событий, редкие поля могут не попасть.
- Детекты создаются с `alert: false` и без нотификаций — подключение уведомлений в Graylog.
- Экстракция значений из `message` не выполняется: если поля нет, сначала нужен экстрактор.
